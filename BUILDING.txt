Building PlanTint from source

REQUIREMENTS
  Node.js 22 or newer and npm. Building the Windows installer on Windows needs nothing
  else; building it on Linux also needs Wine (32- and 64-bit) for the installer step.

BUILD
  npm install
  npm run build      bundles the app into dist/app
  npm start          runs it (Electron)
  npm run dist       makes release/PlanTint-Setup-<version>.exe and the portable .exe

LAYOUT
  src/main/          Electron main process: window, file dialogs, file writing, the
                     close/save handshake and crash-recovery copies, one tab per drawing (main.js, preload.js)
  src/renderer/      the interface: the tab strip (tabs.html, tabs.js, tabs.css), tools
                     (tools.js), drawing of the sheet and markups
                     (render.js), side panel (panel.js), dialogs and the painted-colour
                     finder panel (dialogs.js), open/save/export (io.js), undo (history.js);
                     measuring: scale and units (units.js, scale.js), visible areas and
                     perimeters (measure.js), dimensions and area tags (annot.js),
                     Excel and CSV schedules (schedule.js); the progress map (progress.js,
                     progresspanel.js), snag pins and their photos (pins.js, snagpanel.js),
                     the Excel writer with pictures (xlsx.js) and the progress and snag
                     reports (reports.js); highlights covering colour already on the drawing
                     (covers.js); the markups window, a window of its own that the drawing
                     page fills in and keeps up to date (markupswin.js); merging markups
                     (merge.js, with geom.js mergeRings)
  src/engine/        a Web Worker that owns the drawing's pixels: renders PDFs with MuPDF,
                     decodes pictures, fill, painted-colour search (detect.js), colour
                     removal (imgproc.js unpaint), snapping (a PDF's own line geometry,
                     else the edges of the ink), and every export (PNG, JPEG, PDF)
  src/shared/        code used by both: border line styles (linestyle.js)
  assets/            icons (tools/make_icons.py draws them), and installer.nsh: additions to
                     the Windows installer (one progress bar for the whole installation)
  build.mjs          esbuild bundling, icon set, fonts, MuPDF files

TESTS
  test/run_all.sh runs everything on Linux. It needs xvfb, xdotool (t7 clicks and types with
  the real mouse and keyboard; without it those checks are skipped), python3 with numpy, scipy,
  pillow, pypdfium2, pikepdf, reportlab and openpyxl, plus poppler-utils, ghostscript and qpdf.
  The first run draws the test drawings into testdata/out (testdata/*.py).
    test/harness/    runs the engine in Node to write PDFs without the interface
    test/pdfcheck/   renders PDFs with MuPDF, PDFium, Poppler and Ghostscript and compares
                     them with the expected result (check_app.py compares the app's own PDF
                     exports with its PNG export; check_layers.py checks layer settings)
    test/e2e/        drives the built app with Playwright: t0 is the 1.0 behaviour, t1 to
                     t5 are the five 1.1 fixes (PDF export, rectangle guides, line styles,
                     painted colour, eraser), t6 is measuring (1.2), t7 is tabs (1.4), t8 is crash recovery with several copies (1.3),
                     t9 is the progress map and snag pins (1.5; it reads the Excel reports with openpyxl),
                     t10 is highlights covering colour already on the drawing (1.5.1),
                     t11 is the markups window (1.6), t12 is merging and the window beside
                     the drawing (1.7)
    test/unit/       Node tests of units, typing lengths, visible areas and schedules
                     (measure_test.mjs), of progress, pins and the Excel writer (progress_test.mjs),
                     and of finding and taking out paint under highlights (cover_test.mjs),
                     and of merging shapes (merge_test.mjs)
                     (check_annots.py checks dimensions and tags in exported PDFs)
  Set PLANTINT_TEST_OUT to choose where results go (default: the system temp folder), and
  PLANTINT_NO_BUILD=1 to test the build already in dist/app (for example the minified one
  that npm run dist packages: node build.mjs --minify first).

FILE FORMAT
  A .plantint project is a zip: project.json (markups, legend, style, scale and the
  colour-removal steps), the original drawing under source/, and one run-length mask per
  colour-removal step under ops/. Version 2 adds border line styles, the drawing scale
  and several paint colours per removal step. Version 3 adds the calibration (calib),
  measuring settings (meas), dimensions (dims) and dragged tag positions (tagAt); it still
  writes scale/scaleSource so 1.1 reads the scale. Version 4 adds the progress map
  (progress: on, by, labels; and prog: st, pct, units on each markup), the snag pins (pins:
  id, n, x, y, note, trade, status, photo, raised, closed; pinNext, the next number) and
  their photos (photos: id, file, w, h), stored as JPEG files under photos/. Version 1 to 3
  files open unchanged. Since 1.5.1 a markup may have cover: false (it tints the colour
  painted on the drawing instead of covering it); without it a markup covers that colour.
  The colour taken out under covering highlights is worked out again when a project
  opens (engine: setCovers, imgproc: coverPaints and unpaintPixels); nothing is stored.
